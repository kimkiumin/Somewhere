# 인원 선택 및 상단 프로필 메뉴 설계

## 상태

사용자 승인 설계 (2026-08-12)

## 목표

식당 탐색 조건에 일행 수를 명시해 공유 메뉴의 가능 여부와 추천 기준에 전달할 최소 입력을 만들고, 반복 조건 화면에서 프로필 수정 링크를 제거해 식이 조건·알레르기 관리를 상단 프로필 메뉴의 환경설정으로 이동한다.

## 범위

### 포함

- 조건 화면의 기본 입력 순서를 `함께 가는 인원` → `최대 도보 시간` → `1인 예산`으로 고정한다.
- 인원 선택을 양옆 화살표로 제공한다.
- 선택값은 `1명`, `2명`, `3명`, `4명`, `5명 이상` 다섯 단계다.
- `5명 이상`은 상태 모델에서 `partySize: 5`로 표현하고 화면에서는 `5명 이상`으로 표시한다.
- 선택값 위에 인라인 SVG 폰 실루엣을 반복 표시한다. 활성 인원은 시각적으로 강조하고 5명 이상은 폰 5개와 텍스트로 표시한다.
- 1명에서 왼쪽, 5명 이상에서 오른쪽 화살표를 비활성화한다.
- 현재 선택값을 `aria-live` 영역으로 읽을 수 있게 한다.
- 조건 화면 상단 오른쪽에 원형 프로필 아이콘 버튼을 둔다.
- 프로필 버튼을 누르면 `환경설정`과 `로그아웃` 메뉴를 보여준다.
- 환경설정 화면에서 식이 조건과 알레르기를 검색·목록 다중 선택으로 수정하고 저장할 수 있게 한다. 식이 조건은 비건·락토·오보·락토-오보·페스코·폴로-페스코·플렉시테리언·할랄·코셔·저염으로, 알레르기는 국내 표시 대상 19개 원재료로 구성한다. 각 목록에는 맨 위 `없음`과 네 항목 높이의 내부 스크롤을 제공하며 `없음`은 다른 선택과 상호 배타적이고 저장 시 빈 배열이 된다.
- 저장 후 조건 화면으로 돌아오며 프로필 조건은 추천 조건에 자동 반영된다.
- 예산은 계속 1인 기준으로 유지하며, 이번 변경에서는 메뉴 총액이나 인원별 비용 계산을 구현하지 않는다.

### 제외

- 실제 로그인, 세션, 계정 삭제, 로그아웃 API 또는 인증 공급자 연동
- 인원수에 따른 메뉴 수량·총액 자동 계산
- 인원별 서로 다른 예산·식이 조건 입력
- 5명 이상의 정확한 인원수 입력
- 조건 화면에서 식이 조건·알레르기를 직접 편집하는 컨트롤
- 나침반, 탐색 상태, 공개 수준, 도보·예산 슬라이더의 기존 동작 변경

## 화면 설계

### 조건 화면

상단에는 화면 제목과 오른쪽 프로필 버튼을 둔다. 프로필 버튼은 본문 조건과 분리된 운영 진입점이며, 주요 CTA가 아니다.

본문의 기본 조건 순서는 다음과 같다.

1. `함께 가는 인원`
   - 왼쪽 화살표, 폰 실루엣 행과 현재 인원 라벨, 오른쪽 화살표
   - 기본값은 `2명`으로 둔다. 이는 일행 간 메뉴 충돌이라는 제품 문제를 첫 화면에서 드러내면서 혼자 이용하는 경우도 한 번의 조작으로 선택하게 하기 위한 제품 가설이다.
2. `최대 도보 시간`
   - 기존 5–60분, 5분 간격 숫자 슬라이더와 휠 동작을 유지한다.
3. `1인 예산`
   - 기존 구간형 숫자 슬라이더와 휠 동작을 유지한다.

`이 조건으로 바로 출발`은 조건 화면의 단일 제품 CTA로 유지한다. 프로필 버튼이나 메뉴 항목은 이 CTA를 대체하지 않는다.

### 프로필 메뉴

프로필 아이콘을 누르면 작은 메뉴 또는 패널이 열린다. 메뉴 항목 순서는 `환경설정`, `로그아웃`이다. 현재 인증이 없는 프로토타입에서는 로그아웃을 시각적 운영 항목으로만 제공하고 실제 세션 변경은 수행하지 않는다.

### 환경설정 화면

환경설정은 기존 프로필 편집 화면의 진입점이다. 식이 조건과 알레르기는 각각 검색 가능한 다중 선택 목록으로 제공한다. 저장 버튼은 선택값을 상태에 반영하고 조건 화면으로 돌아간다. 조건 화면에는 편집 컨트롤을 다시 표시하지 않고 적용 상태만 필요할 때 요약한다.

## 상태 및 데이터 계약

조건 상태에 다음 필드를 추가한다.

```js
constraints: {
  category: "restaurant",
  partySize: 2,
  maxWalkMinutes: 20,
  budget: null,
  dietary: [],
  allergies: [],
  disclosure: "minimal"
}
```

`partySize`는 정수 1–5만 유효하다. 5는 `5명 이상`의 화면 표기값이다. 누락, 문자열, 1 미만, 5 초과는 조건 검증 오류로 처리하고 출발하지 않는다. 기존 조건 검증 오류와 같은 방식으로 해당 필드를 식별한다.

인원 변경은 `SET_PARTY_SIZE` reducer action으로 처리한다. 화살표 클릭은 현재값에서 ±1을 계산해 이 action을 dispatch한다. 프로필 메뉴는 `OPEN_PROFILE_MENU`, `OPEN_PROFILE_SETTINGS`, `CLOSE_PROFILE_MENU` 같은 UI action을 통해 기존 profile 화면으로 진입하며, `SAVE_PROFILE`의 기존 프로필 데이터 계약은 유지한다.

## 접근성 및 상호작용

- 왼쪽·오른쪽 컨트롤은 실제 `button`이며 `aria-label="인원 줄이기"`, `aria-label="인원 늘리기"`를 사용한다.
- 경계값에서 비활성화 상태를 `disabled`와 시각적 상태로 함께 표현한다.
- 폰 SVG는 장식 요소로 `aria-hidden="true"`를 사용하고, 현재 인원은 텍스트 라벨과 live 영역으로 제공한다.
- 프로필 버튼은 `aria-label="프로필 및 앱 메뉴"`를 갖고, 메뉴가 열리면 키보드로 환경설정과 로그아웃을 선택할 수 있어야 한다.
- 메뉴 바깥 클릭 또는 Escape로 프로필 메뉴를 닫을 수 있어야 한다.
- reduced-motion 환경에서 폰 선택에 애니메이션을 추가하지 않거나 즉시 전환한다.
- 기준 모바일 폭은 390px CSS viewport로 잡고, 320px까지 가로 스크롤 없이 축소한다. iPhone 14/15급과 소형 Android 폭을 함께 확인한다.

## 오류 및 안전

- 유효하지 않은 `partySize`는 기존 조건 오류 표시 영역에 `함께 가는 인원` 오류를 표시한다.
- 프로필 저장 실패를 시뮬레이션하는 별도 네트워크 상태는 이번 범위에 포함하지 않는다. 저장은 현재 프로토타입의 동기 상태 갱신으로 처리한다.
- 프로필 메뉴를 열어도 조건 입력과 나침반 없는 탐색 전 상태에는 변화가 없다.

## 검증 계획

### 상태 테스트

- 기본 상태의 `partySize`가 2인지 확인한다.
- `SET_PARTY_SIZE`가 1–5 범위에서 값을 바꾸고 경계 밖 값은 거부하는지 확인한다.
- partySize 누락·0·6이 출발을 막고 필드 오류를 반환하는지 확인한다.
- 기존 예산·도보 시간·프로필 저장 테스트가 계속 통과하는지 확인한다.

### 화면 테스트

- 조건 화면에 인원 선택이 도보 시간 위에 렌더링되는지 확인한다.
- 선택값에 맞는 폰 개수와 `5명 이상` 라벨이 표시되는지 확인한다.
- 프로필 수정 CTA가 조건 화면에 없고 상단 프로필 버튼이 있는지 확인한다.
- 프로필 메뉴에서 환경설정·로그아웃이 표시되는지 확인한다.

### 컨트롤러 테스트

- 화살표 클릭이 partySize를 ±1 조정하고 경계에서 멈추는지 확인한다.
- 프로필 버튼 → 환경설정 → 저장 흐름이 기존 profile 상태를 갱신하는지 확인한다.
- 단일 출발 CTA가 유효한 partySize와 기존 조건을 함께 reducer에 전달하는지 확인한다.

### 브라우저 확인

- 조건 화면에서 인원 선택이 도보 시간 위에 보이는지 확인한다.
- 1명, 2명, 5명 이상 경계의 폰 표시와 화살표 비활성 상태를 확인한다.
- 프로필 버튼을 눌러 환경설정에 들어가 식이 조건·알레르기를 검색·선택·저장하는지 확인한다.
- 로그아웃 항목은 존재하지만 인증 상태를 변경하지 않는 프로토타입 항목임을 확인한다.

## 검증할 제품 가설

일행 수를 첫 조건으로 명시하면 개인 예산만 입력했을 때보다 공유 메뉴가 가능한 장소를 추천 기준에 전달하기 쉬워지고, 조건 화면에서 프로필 편집을 분리하면 반복 탐색 흐름의 인지 부담이 줄어든다. 이번 프로토타입은 추천 품질 자체가 아니라 입력 구조와 흐름 이해 가능성을 검증한다.
