# Somewhere vNext 앱 시퀀스

Status: 사용자 확정 시퀀스 (2026-07-26), 조건 화면 갱신 (2026-08-12)

이 문서는 Somewhere vNext 앱의 화면 순서, 정보 공개 시점, 나침반 상태, Stop 및 복구 흐름을 정의한다. 시퀀스에 관해 다른 문서와 표현이 다르면 이 문서를 우선한다. 시각 디자인, 실제 추천 품질, GPS, 장소·경로 API, iOS 및 물리 나침반 구현은 이 문서의 범위가 아니다.

## 1. 시퀀스 원칙

- 사용자는 후보 목록을 보지 않고 한 번에 목적지 하나만 받는다.
- 조건 입력과 장소 탐색 중에는 나침반을 표시하지 않는다.
- `이 조건으로 바로 출발` 버튼 한 번으로 탐색을 시작한다.
- 적합한 장소와 경로가 준비되면 별도의 시작 버튼 없이 나침반 안내가 자동으로 시작된다.
- 일반 안내 화면에는 목적지 이름, 정확한 주소, 사진, 평점, 리뷰, 지도와 `목적지 확인` 버튼을 노출하지 않는다.
- 목적지 정보는 Stop으로 안내를 일시정지한 뒤에만 확인할 수 있다.
- Stop은 이유를 묻기 전에 방향 안내를 즉시 멈춘다.
- 도착하면 목적지와 마지막 접근에 필요한 구체적인 정보를 자동으로 공개한다.
- 활성 Reroll은 두지 않는다. 안내 종료 후 새 추천은 별도의 복구 흐름으로 처리한다.

## 2. 기본 시퀀스

```text
첫 실행 온보딩
→ 조건 입력
→ 장소 탐색
→ 나침반 안내
→ 목적지 근처
→ 도착 및 상세 정보 공개
→ 60분 이후 장소 반응
→ 완료
```

### 2.1 첫 실행 온보딩

서비스의 핵심 약속과 목적지가 당분간 숨겨진다는 점을 짧게 설명한다. 위치 권한은 실제로 필요한 시점에 운영체제 권한 창을 통해 요청하며, 앱 안에서 같은 의미의 확인 버튼을 한 번 더 요구하지 않는다.

첫 실행에서만 식이 조건과 알레르기를 별도 프로필 설정 화면에서 선택한다. 이후 조건 화면에는 이 두 항목을 반복 편집하지 않으며, `프로필 수정`으로 프로필 화면에 들어가 검색 또는 목록 선택으로 변경한다.

### 2.2 조건 입력

기본 화면에 표시하는 항목:

- 장소 종류: 음식점으로 고정한다. 카페는 후속 범위로 보류한다.
- 최대 도보 시간: 5~60분, 5분 단위 숫자 슬라이더
- 예산: 구간형 숫자 슬라이더. 선택값은 `2,000 · 4,000 · … · 20,000 · 30,000 · 40,000 · 50,000원 이하 · 상관없음`이다.
- 기본 버튼: `이 조건으로 바로 출발`

도보 시간 슬라이더는 마우스가 슬라이더 위에 있을 때 휠을 올리거나 내려도 5분 단위로 조정된다. 예산 슬라이더의 일반 선택은 2만원까지 2,000원 단위, 그 이상은 10,000원 단위다. 휠 입력은 1,000원 의도로 처리하되 홀수 천원 값에 정착하지 않도록 유효한 짝수 천원 값으로 스냅한다. 예를 들어 11,000원에서 내리면 10,000원, 올리면 12,000원이 된다. 목적지 공개 수준은 `최소 정보 공개(도보시간 · 예산 · 주요 메뉴)`를 기본값으로 하고, 선택적으로 `비공개`를 고를 수 있다.

이 구간형 스케일은 넓은 범위의 비선형 슬라이더에 주기적 라벨을 둘 수 있다는 [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/sliders)와, 객관적 값에는 각 단계가 의미 있게 구분되는 불연속 슬라이더를 사용하라는 [Material Design](https://m1.material.io/components/sliders.html) 원칙을 따른다. [GOV.UK range slider 지침](https://design-system.service.gov.uk/patterns/question-pages/#using-range-sliders)에 따라 드래그 외에도 키보드와 휠 입력을 제공한다. 기준 문서 확인일: 2026-08-12.

`고급 설정` 안에 접어 두는 항목:

- 접근성 조건
- 목적지 공개 수준

프로필에서 저장한 식이 조건과 알레르기는 조건 화면의 적용 상태 요약에는 반영하지만 이 화면에서 직접 편집하지 않는다. 필수 조건을 만족하는 장소가 없으면 조건 화면으로 돌아오며, 어떤 조건을 다시 확인해야 하는지 표시한다. 조건을 몰래 완화해 장소를 제시하지 않는다.

### 2.3 장소 탐색

`이 조건으로 바로 출발`을 누르면 즉시 탐색 상태로 이동한다.

- 후보 목록을 표시하지 않는다.
- 목적지 정보를 표시하지 않는다.
- 나침반을 표시하지 않는다.
- 적합한 장소와 이동 경로가 준비되면 자동으로 나침반 안내로 넘어간다.
- 사용자가 다시 누르는 두 번째 시작·확정 버튼은 없다.

### 2.4 나침반 안내

나침반은 처음부터 최종 크기로 나타나며 상태가 바뀌어도 커지거나 작아지지 않는다.

표시 순서:

```text
고정 크기 나침반
남은 거리
대표 메뉴 또는 넓은 장소 분류
가격대
현재 안내 상태
Stop
```

바늘의 상태 표현:

- 방향 신뢰도가 충분함: 검증된 실제 진행 방향을 가리킨다.
- 방향을 확인하거나 경로를 다시 계산하는 중: 특정 방향을 가리키지 않고 계속 회전한다.
- 사용자가 Stop을 누른 상태: 즉시 멈추거나 숨긴다.
- 동작 줄이기 설정이 켜짐: 회전 대신 방향 미확정 상태를 정적인 형태와 문구로 표현한다.

`목적지 근처` 상태에서도 나침반 크기와 정보 구조는 그대로 유지하고 거리와 상태 문구만 바꾼다.

### 2.5 도착

도착이 확인되면 방향 안내를 끝내고 다음 정보를 자동으로 공개한다.

- 상호명
- 정확한 주소
- 건물명
- 층과 호수
- 입구 또는 마지막 접근 안내
- 외부 지도 열기
- 완료

공식 자료나 현장 근거가 없는 항목은 추정하지 않고 `정보 없음`으로 표시한다. 사용자가 건물 주변에서 맴돌지 않도록 확인된 마지막 접근 정보를 가능한 한 구체적으로 제공한다.

## 3. Stop 이후 시퀀스

```text
나침반 안내 또는 목적지 근처
→ Stop
→ 즉시 일시정지
```

일시정지 화면의 선택지는 다음 세 가지다.

1. `안내 계속`
2. `목적지 정보 확인`
3. `안내 종료`

### 3.1 안내 계속

같은 목적지와 같은 여정을 유지한다. 센서나 경로를 다시 확인하는 동안 바늘은 방향을 주장하지 않고 회전하며, 방향이 다시 검증되면 실제 방향을 가리킨다.

### 3.2 목적지 정보 확인

```text
일시정지
→ 목적지 정보 확인
→ 확인 이유 선택 또는 건너뛰고 확인
→ 목적지 상세 정보 공개
```

이유 선택지는 짧고 서로 구분 가능하게 유지한다.

- 안전이 걱정됨
- 길이나 입구를 찾기 어려움
- 경로 또는 센서 문제
- 조건을 다시 확인해야 함
- 동행인과 확인해야 함
- 궁금함
- `건너뛰고 확인`

이유는 자유 입력으로 받지 않는다. 목적지를 공개한 뒤에는 다음 선택지를 제공한다.

- `나침반 안내 계속`
- `외부 지도 열기`
- `안내 종료`

한 번 공개한 목적지는 안내 재개, 경로 재계산, 복구 과정에서 다시 숨기지 않는다. 목적지 확인은 안내 종료나 실패로 기록하지 않는다.

### 3.3 안내 종료

```text
일시정지 또는 목적지 공개 상태
→ 안내 종료
→ 종료 확인
→ 종료 이유 선택 또는 건너뛰기
→ 종료 완료
```

종료 확인 화면에는 `안내 계속`과 `종료 확인`을 함께 제공한다. 종료 이유는 안내가 실제로 끝난 뒤에만 묻고, 답하지 않아도 종료를 막지 않는다.

종료 이유:

- 안전 문제
- 경로 또는 센서 문제
- 필수 조건 불일치
- 장소 현장 문제
- 단순 변심
- 일정 변경
- `건너뛰기`

목적지 확인 이유와 안내 종료 이유는 서로 다른 데이터로 취급한다.

## 4. 경로·방향 복구

```text
나침반 안내 또는 목적지 근처
→ 방향 신뢰도 저하
→ 경로 복구
→ 재보정 / 경로 재계산 / 저장 경로 / 외부 지도 / Stop
→ 다시 계산 중
→ 나침반 안내
```

- 방향이 불확실할 때 바늘은 계속 회전하지만 특정 방위를 뜻하지 않는다.
- 기술적 오류로 회전하는 상태와 사용자가 Stop을 눌러 정지한 상태를 명확히 구분한다.
- 외부 지도는 목적지를 공개할 수 있음을 열기 전에 알린다.
- 안전 Stop 뒤에는 자동 재개, 자동 경로 재계산 또는 자동 외부 지도 실행을 하지 않는다.
- 이미 목적지를 공개한 여정이라면 복구 중에도 상호명과 공개 상태를 유지한다.

## 5. 안내 종료 후 새 추천

활성 Reroll 버튼은 없다. 사용자가 안내를 종료한 뒤 직접 `새로운 장소 찾기`를 선택했을 때만 새 추천 흐름을 시작한다.

종료 확인 후 5분 이내라면:

1. 조건 화면으로 돌아간다.
2. 이전 종료 이유를 그대로 보여준다.
3. 종료 이유에 맞는 조건 또는 안전 사항을 확인하게 한다.
4. 확인이 끝나면 기존 `이 조건으로 바로 출발` 버튼을 한 번만 누른다.
5. 새 적합 장소와 경로를 탐색한다.

이 과정에서 실패한 첫 번째 출발이나 두 번째 시작 버튼을 요구하지 않는다. 5분이 지나면 일반 조건 입력 흐름으로 시작한다.

이유별 확인 범위:

- 안전 문제: 자동 재개 없이 안전 관련 조건과 사용자의 명시적 새 추천 의사를 확인한다.
- 경로 또는 센서 문제: 목적지를 바꾸기 전에 재보정, 경로 재계산, 저장 경로 또는 외부 지도 선택지를 검토한다.
- 조건·현장 문제: 문제가 된 조건을 직접 수정하거나 다시 확인한다.
- 단순 변심: 모든 조건을 짧게 다시 확인한다.
- 일정 변경: 현재 여정을 종료하며 자동으로 새 추천을 시작하지 않는다.

## 6. 프로토타입에서 확인할 것

프로토타입은 꾸밈보다 다음 동작이 눈에 보이는지를 검증한다.

- 조건 입력과 탐색 중 나침반이 없는가
- 한 번의 출발 버튼으로 탐색과 안내가 이어지는가
- 일반 나침반 화면에서 목적지가 숨겨져 있는가
- 방향 확인 중에는 바늘이 회전하고 Stop 뒤에는 정지하는가
- Stop 뒤에만 목적지 확인으로 접근할 수 있는가
- 목적지 확인 전에 이유 선택 또는 건너뛰기가 있는가
- 도착하면 상호명, 주소, 건물, 층·호수, 입구 정보가 자동 공개되는가
- 안내 종료 이유와 목적지 확인 이유가 분리되는가
- 5분 이내 새 추천에서 이전 종료 이유를 확인하면서도 출발 버튼은 한 번만 누르는가
- 활성 Reroll이 없는가

실제 GPS, 장소·경로 API, 추천 알고리즘, 계정, 결제, BLE, iOS 센서와 물리 제품은 이 시퀀스 프로토타입에 포함하지 않는다.
