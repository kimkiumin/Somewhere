# Roadmap and Phase Gates

Status: approved design, pending written-spec review

## Operating Principle

Product design and software feasibility run in parallel. The physical compass is a required final deliverable even though the required mockup is not electronically functional.

No phase advances because a date arrived. It advances when its exit evidence exists.

## Phase 0: Canonical Project Baseline

### Work

- user reviews and approves the written blueprint
- reconcile `AGENTS.md`, README, v0.1 docs, and test contracts with approved vNext direction
- establish a safe Git branch and first baseline commit
- preserve the v0.1 prototype as historical evidence
- define decision, hypothesis, and evidence labels in project docs

### Exit Gate

- one documented source priority
- no active instruction requires both immediate Reroll and guarded recovery
- clean distinction between v0.1 history and vNext work

## Phase 1: Feasibility Research

### Software Track

- place-provider capability and rights matrix
- walking-route provider matrix
- menu, price, hours, accessibility, and atmosphere evidence audit
- LLM structured merit-gate spike with a frozen sample dataset
- web location and heading spike
- iOS Core Location and compass spike

### Product Track

- three or more form-factor directions
- full-scale display-window studies
- continuous menu-loop legibility tests
- preliminary control hierarchy
- carry and grip hypotheses

### Exit Gate

- at least one credible place-data path
- at least one credible walking-route path or explicitly accepted test fallback
- demonstrated iPhone heading/location updates on a real device
- selected physical form direction for refinement
- no unresolved dependency falsely represented as implemented

## Phase 2: First Integrated Prototype

### Software Track

- native iOS field-test app
- provider adapter and normalized candidate schema
- deterministic hard filters
- LLM merit interpretation and evidence gate
- uniform random selection
- hidden destination session
- route-aware compass with confidence states
- Stop, reason, reveal, recovery, arrival, and delayed feedback

### Product Track

- refined full-scale mockup
- realistic display animation
- control mockups for Stop and reveal
- CMF candidates
- interaction storyboard showing phone/compass responsibilities

### Exit Gate

- supervised end-to-end journey succeeds on a real route
- all critical safety exits work
- no unsupported place fact reaches the user
- physical mockup is ready for handling tests

## Phase 3: First User Test

### Participants

5-8 participants.

### Focus

- comprehension
- route and sensor failure
- Stop and recovery
- reveal trust
- display readability
- form, grip, carry, and controls

### Exit Gate

- critical issues resolved or explicitly accepted
- event taxonomy stabilized
- Phase 2 study protocol and thresholds frozen
- selected high-fidelity form direction

## Phase 4: Comparative Field Validation

### Participants

20-30 participants in a counterbalanced within-participant comparison.

### Focus

- time to choose
- candidate comparison count
- departure
- selection maintained or reopened
- external interruption
- arrival
- destination reaction

### Exit Gate

- results reported without combining distinct failure causes
- restaurant and cafe results shown separately
- core thesis supported, revised, or rejected explicitly
- next hardware investment decision documented

## Phase 5: Final Product-Design Package

Required:

- high-fidelity physical compass mockup
- verified iOS field experience
- display-motion demonstration
- system architecture and data flow
- provider and legal feasibility record
- research method and findings
- evidence and risk ledger
- final product narrative grounded in results

Stretch:

- BLE functional prototype
- live transfer of bearing, distance, menu, price, and confidence state

## BLE Stretch Gate

Begin BLE integration only when:

- physical form and interaction are stable
- iOS navigation state is stable
- display technology and controller are available
- budget and schedule allow electronics iteration
- failure to complete BLE will not compromise the required final mockup

## Deferred Scope

- standalone GPS/cellular hardware
- production tooling and certification
- Android field app
- accounts and cloud personalization
- payments and reservations
- community features
- broad category expansion beyond restaurant and cafe tests

These are not rejected forever. They require evidence from the current roadmap before entering scope.
